## A restart used to turn every season pack back into one card

`STREMIOSRV_LIBRARY_UI` is off by default and this release touches nothing else.

Only pinned torrents are re-added to the libtorrent session at startup — everything else is
ordinary cache with no reason to be loaded, and no handle. But per-file facts came from that handle
alone, so after any restart a season pack lost the ability to describe itself: one card, carrying
the PACK's name and the whole directory's size, saying nothing about which episode was actually
there. A restart is not an unusual state to be in. Changing any setting on the appliance restarts
the container, so the first thing an owner did after turning the page on put them straight into it.

The files are on the disk either way, and a directory listing answers the question the handle was
being asked for. Each video file in the entry's directory becomes its own row with its own name and
size, whether or not the session knows the torrent — and a single episode gets a row too, because
the entry is named after the torrent and one row is what says WHICH episode is there.

Progress comes out honest because the size on disk and the eventual size are different numbers:
libtorrent allocates a torrent sparsely, so a file reports what it will eventually be while its
allocated blocks report what has arrived. The same helper the evictor already uses to keep the
cache total from counting bytes nobody has downloaded gives each file its real progress here.

A listing is not the torrent's own file list, though, and the page no longer treats it as one. A
directory knows what LANDED — not the torrent's file order, and not how many files it has. So an
addon's file index is not matched against it, and "this torrent has one file, therefore that file
is the release" is not concluded from it: a pack holding a single episode would otherwise answer
"already here" for every other episode in the season.

**Upgrade:** pull it. No configuration changes and no route changes on the default surface.
