## The addon install link was missing on the sign-in that needs it

`STREMIOSRV_LIBRARY_UI` is off by default and this release changes nothing else.

The library page carries the addon's install URL — the only place it appears. That panel unhides
when its loader runs, and the loader ran from the page's start-up path only. Signing in through the
form, which is what happens on a device's **first** sign-in, rendered the whole library and skipped
it: you arrived at a working library on the one visit where you wanted to install the addon, and
found nothing to install it with. It appeared on the next reload, which is no help to anyone who
did not know to try that.

Both paths now load it. The test that was supposed to prevent exactly this asked whether every
loader is called *somewhere* — and it was, from start-up — so it passed while a whole sign-in path
skipped the call. It now asks the stronger question it always meant: every path that renders the
library must also load the panel.

**The README now says how to install it**, in four steps, because the panel alone was never enough
documentation. It also names the mistake the missing panel invites: pasting the address of the
library page instead of the addon URL, which makes Stremio report `Failed to fetch: expected value
at line 1 column 1` — it asked for a manifest and was handed the page's HTML.

**Upgrade:** pull it. No configuration changes and no route changes.
