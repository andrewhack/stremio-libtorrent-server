## Refuse a playlist that arrives cut short

A playlist fetched through `/proxy` — or through the transcode reader for an external stream — whose
upstream declared a `Content-Length` but then closed before sending all of it was rewritten and
served as if it were complete, so the player received a playlist missing its later segments. The
server now notices the short read and answers `502` instead of a truncated `200`, on both paths. A
compressed or chunked playlist cut short was already refused; this closes the plain case.

**Upgrade:** pull it.
