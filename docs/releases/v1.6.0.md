## A season pack now answers for every episode it holds

`STREMIOSRV_LIBRARY_UI` is off by default and this release changes nothing else.

The addon offered a local stream on exactly one episode page per pack. A torrent has one infohash,
the server records one label against it, and that label names the single episode the download was
started for — so a pack holding six episodes matched on one of them and stayed silent on the other
five. The episode you were looking at almost never was the one the label named.

The pack's own file names know which episodes are inside, and this server already reads them: the
download path picks an episode out of a pack that way. The stream resource now does the same. It
matches the title on the label's id alone, then resolves the episode you asked for against the
files, so every episode actually on disk gets a row and the rest correctly get nothing.

**It also stopped counting boundary spill as an episode.** A piece straddles the boundary between
two files, so fetching one leaves a few megabytes of its neighbours behind. Those were being
reported as present — enough for the meta page to list two episodes nobody has, plus a pair of text
files, as though they were watchable, and enough for the addon to have offered a stream that stalls
on the first seek. The library page had always drawn that line correctly; the rule it used is now a
named function both it and the addon share, so there is one answer to "is this file really here"
rather than two that disagree.

**Upgrade:** pull it. No configuration changes and no route changes.
