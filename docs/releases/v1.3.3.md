## HEAD works on the transcode routes, and the lint surface stops moving on its own

**A client that sends `HEAD` before playing no longer fails on the transcode path.** The `hlsv2`
routes — `/probe`, `/master.m3u8` and the segment route — answered `405 Method Not Allowed` to a
`HEAD` request, while the byte-range route answered normally. FastAPI, unlike bare Starlette, does
not add `HEAD` to a route declared with `@router.get`, and the byte-range route was the only one
that had ever declared both methods explicitly. So a client probing a URL before playing it hit a
hard failure on exactly one surface, which is why this went unnoticed for so long. The three read
routes now accept both methods and return identical headers with an empty body.

`/{id}/destroy` is deliberately left out. `HEAD` is defined as a safe method, and that route tears a
transcode job down — a crawler, proxy or link-checker sending `HEAD` must not be able to end
someone's playback. A `HEAD` to it now falls through to the segment route and 404s; the teardown is
never reached.

The conformance harness gained a `head-parity` check that compares `HEAD` against `GET` on both
surfaces, so this cannot regress silently.

**Lint tooling no longer changes behaviour on its own.** The project was clean against its pinned
linter and reported dozens of findings against a newer one — with no source change. The newer
release had widened its built-in *default* rule set, so the standard the code was measured against
moved underneath it. Fixing the findings would have left that trap armed for the next upgrade, so
the rule selection is now declared explicitly in `pyproject.toml`. Upgrading the linter changes
behaviour only when that list is edited.

Most findings were mechanical and are fixed. A handful are exempted with stated reasons rather than
silently: `try/except/pass` blocks here each carry a comment explaining why the exception is safe to
swallow, which a terser construct would delete; and the FastAPI parameter markers that appear in
argument defaults are the framework's own signature idiom, not the mutable-default bug that rule
exists to catch. The declared Python target was also corrected to match the version the package
actually requires.

**Documentation.** A "still TODO" section in the protocol map had outlived its work — the captures
it asked for sat directly beneath it and had long since become the conformance fixtures. It now
records that as done and names what is genuinely unmapped instead. The Docker Hub overview was
within a few hundred bytes of its length limit, which is one edit away from blocking a release; two
reference sections moved to the GitHub README with pointers, leaving roughly six kilobytes of room.

**Upgrade:** pull it. No configuration changes, and no behaviour changes to playback, the engine or
the API beyond `HEAD` now being answered where it previously was not.
