## Two ways the library manager judged the wrong thing

`STREMIOSRV_LIBRARY_UI` is off by default and this release touches nothing else. If you do not set
it, there is nothing here for you.

**The download gate applied the pin guard, and refused nearly everything.** A pin can never be
evicted, so before accepting one the server checks that finishing it would still leave the whole
cache budget plus ten percent free beside it — otherwise ordinary streaming has nowhere left to
buffer. The library's Download button was asking that same question, and it has not been the right
question since downloading stopped pinning: a download is ordinary cache, and the evictor manages
it like anything else. Asked of a download, the rule wants more free space than most disks hold —
the entire budget, *on top of* the release — so releases were greyed out on a disk with room for
several of them. Including every release whose size no addon reported, because an unknown size
falls to the same check and there was nothing left for it to pass.

The button now asks only whether the disk can spare it, holding back the larger of 2 GiB and 2% of
the disk so a download cannot fill it out from under the logs, the resume files and the transcode
segments. A download that would push the cache past its *budget* is still offered and still marked
in red: the evictor may reclaim it before it is watched, which is a warning, not a refusal. The pin
guard keeps its own rule unchanged, because a pin really does have to reserve the budget.

**A release inside a busy torrent could not be asked for.** A season pack is ONE infohash, and the
release list read each button from the torrent — so while one episode was downloading, every other
episode of that pack read "Downloading" and was disabled. Nothing had asked for those files: the
torrent was busy, the episode was not. This is the third thing to go wrong the same way, after the
episode ticks and the on-disk badge, and it has the same fix: describe the FILE, not the torrent it
happens to share. A button now matches the addon's own file index where a release carries one, and
the episode number against the torrent's file list otherwise. A torrent entry carries its per-file
state and its total file count, which is what tells a single-file release apart from a pack with
one episode selected; a torrent whose files nothing in the session knows still falls back to its
own state, as before.

**And Keep kept nothing.** On a release the server already held, the button labelled Keep called
the download route — which since the same split wants a file without protecting it. It pins now,
through the one code path the card's Keep control already used, which is also the only place the
out-of-space answer is handled.

**Upgrade:** pull it. No configuration changes, and no route changes on the default surface — the
library routes exist only while the experimental flag is on.
