## Three fixes found by comparing against a fork

`docker/launch.sh` has been building an incomplete `docker run` since v0.2.21: a blank line inside
the continued command ended it early, so the container came up without its health check, monitor
labels and log limits — and on most hosts did not come up at all. A test now runs the script and
checks the command it builds.

The VAAPI transcode path never converted the pixel format, so a 10-bit source reached an 8-bit
encoder with nothing in between. It now converts, with and without a scale width, the way the NVENC
path always has. This one is reasoned from the code path and ffmpeg's documented behaviour rather
than measured on VAAPI hardware.

An ffprobe that does not answer used to become a 500. Playback now answers 504, and the subtitle
list answers its ordinary empty list and says so in the log.

**Upgrade:** pull it.
