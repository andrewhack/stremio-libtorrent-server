## Release tooling only — no change to the streaming server

Nothing under `src/` or `tests/` differs from 1.2.0. The engine, the API and the player behave
exactly as they did. This release exists to exercise the new one-command release path end to end,
and to get the corrected Docker Hub page published.

**Publishing is now one command.** `docker/publish.sh` does the whole release: build → smoke-test →
push `:$VERSION` and `:latest` → sync the Docker Hub overview → tag → cut the GitHub release. It
replaces a throwaway script per release, each a copy of the last with the version retyped in four
places — a pattern that had quietly gone stale.

- The version is **read out of the image being pushed**, not typed. The old script's default said
  `0.2.4` long after 1.2.0 shipped, so a run that forgot to override it would have republished a
  stale build *and* moved `:latest` onto it.
- It refuses to build from a tree with uncommitted changes, and refuses to publish an image whose
  version disagrees with the checkout.
- The smoke gate starts the image and polls `/health` until it reports healthy, failing with the
  container logs if it never does, or if the version it serves is not the version being tagged.

**The Docker Hub overview is current again.** It had drifted two releases behind the README, missing
the DHT routing-table persistence from 1.1.0 and the whole next-episode prefetch section from 1.2.0 —
because pushing an image never updates that page. It is now synced as part of every release. Docker
Hub caps it at 25,000 **bytes** (not characters, which is easy to get wrong when emoji cost four
each), so repo-facing sections are marked `<!--hub:skip-->` and omitted there while GitHub keeps the
full README.

**Upgrade:** nothing to do. `1.2.1` and `1.2.0` run identically — pull it only if you would rather
your tag matched the current documentation.
