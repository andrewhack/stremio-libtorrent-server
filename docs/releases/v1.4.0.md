## The library page is worth telling you about now

It has been in the last few releases behind `STREMIOSRV_LIBRARY_UI`, unmentioned except as a line in
the settings table. It is still **off by default** and still an authenticated page you have to turn
on deliberately — nothing about the default surface changes. But it has stopped being an
experiment, so the README says what it is: turn it on and the server stops being a passthrough. You
can queue a download before you sit down, see which episodes of a pack are actually on the disk
rather than one folder-sized number, and keep the ones you want protected from the cache evictor.

**It now shows what it is giving back.** Both places that painted a transfer rate were gated on a
title still downloading, so a finished title that was seeding said nothing at all — the one number
that tells you the box is doing its share was the one number missing. A seeding title now carries
its upload rate, and a downloading one shows both directions with arrows, because two bare rates on
one line cannot be told apart.

It is silent when nothing is being pulled, which is deliberate rather than an oversight. An upload
rate of zero means two different things — a loaded torrent nobody wants right now, and a title with
no torrent loaded at all, which after a restart is most of the cache — and printing `0 B/s` would
report the second as if it were the first.

The row also refreshes for seeding titles now, not only downloading ones. It is updated in place
between polls, and a rate that is painted once and never again is worse than no rate at all: a
stale number looks live.

**Upgrade:** pull it. No configuration changes and no route changes on the default surface — the
library routes still exist only while the flag is on.
