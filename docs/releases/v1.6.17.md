## A destination guard for the routes that fetch a URL

The routes that take a URL from the client — subtitle fetches, the opensub hash, and the transcode
probe and playlist routes — now apply the same destination rule `/proxy` already uses: a client on
the home network may reach anything but link-local and cloud-metadata addresses; a client from the
internet, or a web page on another site, only public addresses. ffprobe and ffmpeg no longer open a
client's URL directly — the server fetches it, re-checking every redirect — so a server reachable
from the internet cannot be used to reach its own network or read local files. Every stream that
transcoded before still transcodes.
