## A destination guard for the routes that fetch a URL

The routes that take a URL from the client now refuse to reach where the client itself could not.
Subtitle fetches (`/subtitles.<ext>?from=`) and the transcode probe and playlist routes apply the same
destination rule `/proxy` already uses: a client on the home network may reach anything but link-local
and cloud-metadata addresses; a client from the internet, or a web page on another site, only public
ones. ffprobe and ffmpeg no longer open a client's URL directly — the server fetches it through a
loopback-only reader and re-checks every redirect. Separately, the opensub-hash route no longer reports
whether a local path exists or how big it is. So a server reachable from the internet can no longer be
steered, through a URL a client hands it, into fetching from its own network.
