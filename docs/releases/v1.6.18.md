## Media-fetch reader follow-ups

Follow-ups to 1.6.17's destination guard, all on the loopback reader that ffmpeg uses for an
external or proxied media URL:

- A long proxied HLS playlist no longer loses its earliest segments. The reader keys each segment
  through the guard by a ticket; the previous ticket bound was small enough that a playlist of many
  segments evicted its own early ones before ffmpeg fetched them.
- An authenticated proxied HLS stream now carries its request headers to the segments on the same
  origin as the playlist, so per-segment authentication no longer fails. A segment on a different
  origin is never handed those headers.
- A destination-guard refusal is now logged, so a refused media or subtitle source is visible in
  the server log instead of surfacing only as a 403 or 502 to the player.
