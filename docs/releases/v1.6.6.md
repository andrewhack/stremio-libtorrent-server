## Complete files on a compressing filesystem count as complete

**Library addon** — on a filesystem that compresses (ZFS, btrfs), a finished file takes less space
than its length, and the server measured what had arrived by that space. A complete episode read as
just short of complete, and the addon would not offer it. Arrival is now measured by the file's
holes, which compression does not change. `/stats.json` also counts the addon's subtitles requests
(asked, reported a file, title learned), and the count of learned titles reaches the container log.

**Library UI** — the same files no longer read a fraction short of complete.

**Upgrade:** pull it. No configuration changes.
