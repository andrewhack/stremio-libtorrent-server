# The server keeps its own free-space reserve, and /health watches the disk

The library page held back some free space before offering Download, but the server did not, so
anything calling the API directly could fill the disk.

- The server now refuses a download while free space, less what running downloads still need, is
  already inside the reserve (the larger of 2 GiB and 2% of the disk). The page reads the same
  reserve from the server.
- `/health` has a `disk` component: degraded while the disk is inside the reserve, and unhealthy
  if it cannot be measured.

**Upgrade:** pull it. A server whose disk is already inside the reserve reports degraded after the
upgrade; free some space or lower the cache size.
