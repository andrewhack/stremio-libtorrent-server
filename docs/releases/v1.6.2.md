## Abandoned transcodes are ended instead of running forever

A crashed or failed player never calls `/destroy`, and the housekeeping sweep spared any job whose
ffmpeg was alive — so a transcode nobody was reading was protected by its own liveness, pinning a
core and holding GPU memory indefinitely. Repeated attempts stacked several at once, since each
carries a fresh job id. Reported as [#2](https://github.com/andrewhack/stremio-libtorrent-server/issues/2).

Playlist and segment requests now count as activity, and a job nothing has read for
`STREMIOSRV_TRANSCODE_IDLE_TIMEOUT` seconds (default 300) has its ffmpeg ended and its output
reclaimed. Housekeeping runs every 60s instead of every 300s, so a finished encoder is also reaped
promptly rather than lingering as a defunct process.

Also in this release: the library addon offers a file only once it has finished downloading. A
partial file stalls on first open and its row showed the full declared size, which read as though
the whole episode were already on disk.

**Upgrade:** pull it. No route changes.
