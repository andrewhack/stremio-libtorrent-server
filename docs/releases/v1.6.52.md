# Hardware transcoding finds its GPU, and falls back when it fails

The server looked for one GPU device, `/dev/dri/renderD128`, and assumed it could encode. A GPU
behind another node went unused, and one that could not encode H.264 failed every transcode.

- Every GPU node under `/dev/dri` is tried at startup with a short test encode; the first that works
  is used, and the log says which.
- A transcode that fails on the GPU before it starts is restarted on the CPU instead of failing the
  play.
