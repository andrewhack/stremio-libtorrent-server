## The library's sign-in panel now points at the player instead of describing it

`STREMIOSRV_LIBRARY_UI` is off by default and this release touches nothing else.

A server using the shared `stremio.rocks` certificate cannot offer a password box: that
certificate's private key is public, so anything typed against it is readable by anyone on the
path. The library page says so and sends the owner to sign in to the web player first, because a
session made there is one the page can read.

It said to open the player "on this address" and left the address to be worked out, and the
obvious attempt fails in a way that explains nothing. The player is served on two ports — one
plain HTTP, one HTTPS — and a browser given a trusted hostname will reach for HTTPS on whichever
port it is handed. Aimed at the plain one that produces `SSL_ERROR_RX_RECORD_TOO_LONG`, an error
about record length that never mentions the port, on a page that looks like the right place to be.

The panel now links to the player at the root of the origin the page is already on: same scheme,
same host, same port, nothing to retype. That also happens to be the only address that works, for
a reason worth stating — the session lives in the browser's per-origin storage, so signing in at
`https://<ip>:12470` grants nothing to `https://<trusted-name>:12470`. They are different origins
and each keeps its own. A relative link cannot get that wrong.

**Upgrade:** pull it. No configuration changes and no route changes on the default surface.
