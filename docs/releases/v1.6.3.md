## Remove works for a title the session never loaded

Both remove paths resolved a torrent's on-disk name from the running session, and only pinned and
wanted torrents are re-added there at startup — so an ordinary cached title was invisible to them.
The library page's Remove deleted nothing and still answered ok, which looked like a dead button;
`/cache/remove` deleted the directory but left the `.parts` holding file behind, which is where most
of the data lives.

Both now fall back to the name index the evictor already consults, behind the same guards, and the
library route reports whether it actually removed anything.

**Upgrade:** pull it. No configuration or route changes.
