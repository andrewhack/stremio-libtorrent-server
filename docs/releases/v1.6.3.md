## Remove works for a title the session never loaded

**Library UI** — Remove did nothing for an ordinary cached title: no data deleted, and it still
reported success, so the button looked dead and the card returned on the next refresh.

**Cache API** — `/cache/remove` deleted the title's directory but left the `.parts` holding file
behind, which is where most of a partly-fetched torrent's data lives.

Both resolved the torrent's on-disk name from the running session, which holds only pinned and
wanted torrents after a restart. Both now fall back to the name index the evictor already uses, and
the library route reports whether it removed anything.

**Upgrade:** pull it. No configuration or route changes.
