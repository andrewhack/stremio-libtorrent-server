## The library publishes itself as a Stremio addon

Turning on the library page used to mean a browser tab: a set of shelves showing what is cached,
downloading, or kept, reachable only by opening that page and signing in. This release adds a second
way in — the same state, read-only, as an ordinary Stremio addon. Turn the library on and the server
also answers as one: a "My Library" row appears on the board alongside whatever other addons are
installed, and every title the box already holds gets a "play the local copy" entry in that title's
normal stream list, right beside every other source. There is nothing extra to enable — the addon is
mounted whenever `STREMIOSRV_LIBRARY_UI` is, and gone whenever it is off.

The catalog Stremio sees is typed `other`. A single row has to hold films, series and anything the
server has no name for at all, and Stremio's catalog types have no bucket for "unidentified" — `other`
is the same type Stremio's own local-files integration uses, for the same reason, and reusing it means
the app already knows what to do with the row instead of tripping over an unfamiliar type.

What that row shows depends on what the server can actually name. It can only put a title and a poster
on an entry it recognises, and the only place it keeps that recognition is `labels.json` — written for
downloads started from the library page, exactly like the page's own shelves. Anything else on disk, a
magnet pasted straight in, or a torrent played before the library existed, is real and addressable and
still appears, just under its on-disk folder name and with no poster. Guessing a title from a folder
name would risk a confident-looking row pointing at the wrong thing, which is worse than an honest,
plain one.

Two independent checks guard every request into the addon: a token baked into the install URL, and the
caller's address has to be on a private network. Either one failing returns a plain 404 — never a 401,
which would at least confirm to whoever is asking that a route exists at all. The 404 for a wrong token
and the 404 for a route that was never there render byte-identical.

The network check exists because the token alone stops being enough the moment the addon is installed:
Stremio syncs an installed addon's URL into the account, onto every device signed into it, which is
also how the URL leaves the LAN it was issued on. The private-network check is what keeps the library
behind that URL from following it anywhere the account goes. `STREMIOSRV_LIBRARY_ADDON_ALLOW` narrows
or widens the default — loopback, private ranges, link-local, IPv6 ULA, carrier-grade NAT — if that
default does not fit your network.

**Upgrade:** pull it. If `STREMIOSRV_LIBRARY_UI` is already on, the addon is live the moment the new
image starts — open the library page for the install link. Everyone else sees no change at all.
