## Fix: peer-starved streams no longer spam the ASGI error log

A stream that ends early — a peer-starved piece, or a torrent the cache evictor removed
mid-stream — logged a full `Exception in ASGI application` traceback and made nginx report
`upstream prematurely closed connection`, as if the server had faulted. It hadn't: truncating
is the correct HTTP signal for an incomplete body, and the player simply re-requests the range.

`wait_and_read` was already written to end the stream cleanly instead of raising, and its
docstring claimed that avoided the ASGI `ExceptionGroup`. It didn't. The range route has already
sent `Content-Length: end-start+1` with the 206, so a short body makes **uvicorn** raise
`RuntimeError("Response content shorter than Content-Length")` after the generator returns —
outside the generator, where its own `try/except` can't reach. The graceful return suppressed
the raise it owned and never touched the one that actually fired.

The wrapper that already absorbed mid-stream client disconnects now also recognises that
specific truncation as an expected end-of-stream. Wire behaviour is unchanged — the connection
still truncates, the player still retries — and `wait_and_read`'s WARNING remains the
diagnostic. Suppressing the exception alone wasn't enough: uvicorn then logs
`ASGI callable returned without completing response.`, so that follow-up is dropped too, scoped
by contextvar to the one request that truncated.

The suppression is deliberately narrow. It matches on the exception message rather than the
type, because a bare `RuntimeError` match would swallow genuine bugs, and the sibling
`"longer than Content-Length"` — which means a range was computed wrong — stays unsuppressed.

**Why the existing tests missed it:** they call the generator directly and assert it doesn't
raise, which was always true. The defect lived one layer up. The new tests drive a real uvicorn
server over a real socket, both with a synthetic short body and through the real playback route,
and each asserts the response actually truncated so it can't pass vacuously. Verified by
mutation: broadening the predicate, making the log filter unconditional, and reverting the fix
each make the suite fail.

Found in production logs on the live server, not by the test suite.

**Upgrade:** `docker pull androshack/stremio-libtorrent-server:1.0.4` (also `:latest`).
No configuration changes, no API changes.
