## Refuse a torrent file that is really a playlist

Completes the 1.6.17 destination guard for one remaining vector: a torrent whose *bytes* are a
crafted HLS/DASH/ffconcat manifest. ffprobe and ffmpeg follow such a file's segment URLs while
probing it — before the after-probe refusal could help — so a manifest listing absolute LAN or
cloud-metadata segment URLs could steer the server into fetching from its own network.

The server now recognises a manifest-headed torrent file and refuses it before ffprobe or ffmpeg
opens it, on the transcode, subtitle and embedded-subtitle paths alike. The check reads the file's
head the same way the player would and waits for it the same way, so a genuine stream is never
misjudged — and a real media file never begins with a manifest signature.
